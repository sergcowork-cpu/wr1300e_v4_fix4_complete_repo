WR1300E V4 FIX4 — исправление финальной проверки (НЕ изменение аппаратной части)

Заменить в существующем репозитории три файла с сохранением путей:
  build_linux.sh
  verify_v3_led_abi.py
  .github/workflows/build.yml
Остальные файлы, включая DTS, config и патчи, не менять.

Причина: лог FIX4 показывает общий manifest ramips/mt7621 до установки пакетов
конкретного устройства. Старый валидатор требовал отдельный manifest с именем
cudy_wr1300e-v2. Фактическое сообщение ошибки в диагностике отсутствует:
stderr не перенаправлялся в final-validation.txt. Это вероятная причина, а не
подтвержденное сообщение валидатора.

Новый валидатор сопоставляет SquashFS, включенный в BIN, с файлом root.squashfs+pkg,
формирует manifest из APK DB соответствующего target-dir, проверяет LED defaults
в этом каталоге. Все прежние проверки ABI, CRC, DTB, GPIO, портов и разделов остаются.
Скрипт сохраняет stderr и profiles.json, workflow сохраняет BIN при сбое в
отдельный артефакт CANDIDATE_DO_NOT_FLASH. Его нельзя прошивать без проверки.

Если в предыдущем запуске уже есть артефакт с BIN, повторную сборку не запускать:
сначала передать архив с BIN и текст ошибки из GitHub Actions.
Если BIN не был опубликован, runner уже завершён и файл не сохранён, понадобится
повторный запуск с этим исправлением. Полная сборка этого патча не выполнялась.
